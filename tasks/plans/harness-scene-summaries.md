# Plan: Harness-session scene with summary rollups

## Intent

Replace the 3D scene's generic recent-activity labels with one voxel character
per agent-harness session. Each harness (omp / claude / pi / codex) has a
distinct look. A character's tooltip shows that session's AI summary — harvested
for free from the harness's existing rollout summaries — or a zero-LLM fallback.
At coarse grains (7d/30d/90d/1y/all) sessions collapse to one character per
(repo × harness) whose tooltip is an LLM-rolled-up summary, computed once,
cached immutably, and committed. LLM spend is bounded to tiny incremental
rollups only.

## Context package

### Relevant existing code

- `data_pipeline/` (Python + DuckDB + uv, `uv run snapshot`): already ingests
  the four harness session dirs (OMP/CLAUDE/PI/CODEX silver templates) plus git,
  aggregates five ranges, LTTB-downsamples, writes `public/data/current.json` +
  `public/data/history/YYYY-MM-DD.json`.
- `components/scene/` (R3F v9 port of `3d-scene-test`): warehouse env, krabs,
  current session labels (drei `<Html>` over `recentActivity`).
- `lib/types.ts` / `lib/data.ts`: snapshot schema + runtime fetch.
- Harness data (verified):
  - `~/.omp/agent/sessions/<repo-enc>/<ts>_<thread_id>.jsonl` (+ `<thread_id>/` subagent/advisor logs) — `cwd` on the `type:"session"` line.
  - `~/.omp/agent/memories/<repo-enc>/rollout_summaries/<thread_id>-<slug>.md` — per-session summaries (frontmatter `thread_id`, `updated_at`; body = 2-4 sentences). These already exist, generated by the harness for free.
  - `~/.claude/projects/**/*.jsonl`, `~/.pi/agent/sessions/**/*.jsonl`, `~/.codex/sessions/**/*.jsonl` — session logs, no summary artifacts found.
- `~/.omp/agent/config.yml` — provider gateway; `deepseek/deepseek-v4-flash` is the cheap role model (rollup default).

### Architectural constraints

- Pipeline runs locally, commits snapshots; frontend is static and never calls an LLM.
- Existing `current.json` fields stay; new fields are additive.
- Rollups are immutable: keyed by `(repo, harness, grain, window-end)`, never regenerated for the same key; skip when the window's content hash is unchanged.

### Prior decisions (confirmed with owner)

- Day grain = one character per session; 7d/30d/90d/1y/all = one character per (repo × harness). To make the per-session view reachable, the range toggle gains a `1d` (Today) option. [assumption to confirm at review]
- Rollup = LLM, cached + immutable, committed in the snapshot.
- All four harnesses render; OMP summaries used where present; everyone falls back to title + repo-day commit stats (no LLM).

### Anti-patterns to avoid

- LLM from the browser (key leak + cost) — all summarization is offline in the pipeline.
- Regenerating cached rollups — immutability + content-hash skip.
- Parsing the repo out of directory-name strings — use the session `cwd` field (authoritative), directory encoding only as fallback.
- Rendering unbounded characters — bound by grain and desk count (top-N by activity).
- Re-summarizing raw sessions at coarse grains — rollup input is always existing summaries/fallback text, truncated to a token budget.

## Behavioral contracts

- GIVEN a snapshot run WHEN the pipeline runs THEN `sessions` contains one entry per session across the four harness dirs with `harness`, `repo` (from `cwd`), `sessionId`, `day` (start-of-session, local tz), and `summary` or `fallback`.
- GIVEN an OMP session with a matching `rollout_summaries/<thread_id>-*.md` file THEN its `summary` = the file body (read, no LLM).
- GIVEN a session without a summary THEN `fallback` = session title when extractable, else repo-day commit stats (`N commits, +X/−Y`).
- GIVEN a `(repo, harness, grain, window-end)` rollup key already cached with an unchanged content hash THEN no LLM call is made.
- GIVEN a new key with content THEN exactly one LLM call produces a ≤150-word paragraph, stored and committed.
- GIVEN a window with no content THEN no rollup key is created.
- GIVEN the scene at `1d` grain THEN one character per session, tooltip = that session's summary/fallback.
- GIVEN the scene at a coarse grain THEN one character per (repo × harness) with activity in the window, tooltip = the rolled-up summary.
- GIVEN a repo × harness with no sessions in the window THEN it does not appear.

## Edge case inventory

- Sessions without summaries (the majority) → fallback path (mandatory, not exceptional).
- Repo has activity but no OMP summaries → commit-stats fallback at every grain.
- Rollup input over budget → truncate to 8K tokens (newest/activity-weighted), never error.
- LLM call fails → record `rollupError` for the key, retry next run; never block the snapshot.
- Session file malformed or missing → skip with a log line, never crash.
- Session spanning midnight → day = local start-of-session date.
- Active entities exceed desk count → top-N by activity fill desks, overflow indicator (small counter, no fake characters).
- Content hash unchanged on re-run → rollup skipped (zero cost re-runs).

## Data model (additive to `current.json`, same fields in history)

```jsonc
{
  "sessions": [
    {
      "harness": "omp",                       // omp | claude | pi | codex
      "repo": "dev-portfolio",
      "sessionId": "01a01037-...",
      "day": "2026-08-17",
      "startTs": "2026-08-17T14:54:57Z",
      "summary": "User reported repo/PR summaries picking up feature branches...", // nullable
      "summarySlug": "feature_branches_mis",   // nullable
      "fallback": "Separate data pipeline from Next.js app · 3 commits, +120/−40"  // nullable
    }
  ],
  "rollups": {
    "7d":  { "dev-portfolio|omp": "This week: …" },
    "30d": { "dev-portfolio|omp": "This month: …" },
    "90d": { "…": "…" },
    "1y":  { "…": "…" },
    "all": { "…": "…" }
  }
}
```

## Pipeline steps (extend `data_pipeline`)

1. Harvest session metadata across the four harness dirs (sessionId, harness, repo from `cwd`, startTs, day).
2. Read OMP `rollout_summaries/*.md`, map by `thread_id` → `summary` + `summarySlug`.
3. Build fallback text (title from session log where extractable; else repo-day commit stats from existing git data).
4. Rollup (LLM, `deepseek-v4-flash` via the harness gateway, endpoint/key from env config): per (repo × harness × grain), input = window's summaries/fallbacks truncated to 8K tokens; output ≤150 words; cache immutably by `(repo, harness, grain, window-end)` + content-hash skip; failures recorded, never fatal.
5. Emit `sessions` + `rollups` into `current.json` and the dated history archive.

## Scene changes (extend `components/scene/`)

- Four harness character archetypes (recolor + small distinct accessory over the existing voxel/krab system): omp, claude, pi, codex.
- Render rule: `1d` → one character per session; coarse → one per (repo × harness); positioned at the repo's desk, top-N by activity capped to desk count.
- Tooltip (drei `<Html>`): session summary at `1d`, rolled-up summary at coarse grains, fallback text where summary is null.
- Range toggle gains `1d` (Today); scene + stat card share the toggle state.

## Cost model

- Day-grain tooltips: $0 (harvested files + fallback).
- Rollups: ~1 call per (repo × harness × grain) per changed window; ~2–8K input tokens, ≤150 output words, at `deepseek-v4-flash` pricing ≈ $0.001/call. Worst realistic snapshot (≈35 new keys) ≈ $0.05–0.15; re-runs within a day are free via content-hash skip.

## Tests

- Session harvest: fixture dirs → correct harness/repo/sessionId/day; summary mapping by thread_id; fallback construction.
- Rollup cache: same key + unchanged hash → zero LLM calls (mock client, assert call count); changed hash → one call; failure → recorded, snapshot still written.
- Token-budget truncation.
- Frontend: schema normalization for `sessions`/`rollups`; scene render prop (per-session vs per-repo×harness) unit tests.
